## Meeting Notes

### Website & Provider Page Updates

* Piyush highlighted significant website improvements completed over the previous two weeks by Denis and community contributors.
* The **Compute Providers** page has been redesigned to provide a clearer view of Akash Network capacity and individual provider information.
* The updated experience includes a global map showing provider locations, live network capacity, detailed provider profiles, GPU median pricing, provider uptime, and other statistics.
* Provider capacity calculations were corrected, while mobile layouts and theme support were also improved.
* Competitor comparison pages continue to receive updates to better communicate how Akash is positioned against alternative compute platforms.
* Denis has also been leading ongoing navigation improvements across the website.
* FAQ crawlability and social preview images were improved as part of the recent provider-related website work.
* Another pending PR redesigns the GPU pricing, users, calculator, and provider landing pages, with review and merging expected after final checks.

### Case Studies, Content & AI Discoverability

* A new **Razer AI Ava Mini case study** was added, highlighting how Akash decentralized compute supported the Razer AI Ava Mini product.
* Community contributors continue publishing content through **The Embed**, including guides and educational material around GPUs, compute, bandwidth, and related topics.
* Piyush noted that this content can also support SEO by expanding relevant content and backlinks associated with the Akash website.
* The Core team added an **AKT CLI agent skill** to Akash Docs to help AI coding agents such as Claude and Codex understand how to perform Akash-related actions.
* The agent skill is available within the deployment section of the documentation and provides structured prompt guidance for interacting with Akash compute.
* The website also added `llms.txt` after Joe previously identified that it was missing.
* The addition is intended to improve how AI agents and LLM-based systems crawl and understand Akash website content.

### Provider Console, Home Node & Provider Playbooks

* Tyler clarified that **Provider Console is no longer the tool for building an Akash provider** and should now be positioned as a provider management interface.
* Provider Console remains useful for monitoring and managing providers and leases, with additional improvements planned for the management experience.
* The official method for building and configuring a full Akash provider is now through the **Provider Playbooks using Ansible**.
* Tyler asked Piyush and Denis to review the website and documentation for outdated references instructing users to create providers through Provider Console.
* Existing links, tiles, documentation, and calls to action should instead direct users toward Provider Playbooks.
* Home Node should be presented as the simpler alternative for users who only want to make compatible GPUs available without operating and maintaining a complete provider.
* Home Node currently supports the **3090, 4090, 5090, and Pro 6000** GPU types.
* Denis proposed creating two clear provider calls to action: users with compatible consumer-grade GPUs can use Home Node, while users with broader infrastructure such as CPU, memory, or other provider resources should use Provider Playbooks.
* Tyler recommended making the distinction explicit: Home Node is for users who want to put supported GPUs online without managing provider infrastructure, while Provider Playbooks are for users who want to build and manage a full provider.
* Piyush identified an existing documentation page that still described Provider Console as a tool for getting providers online.
* Tyler confirmed that this content should be updated and asked for issues to be created for any outdated provider pages so revised copy can be supplied.

### Blackwell Page & Lead Routing

* Tyler raised a question about whether leads submitted through the Blackwell page were correctly flowing through HubSpot to the Akash partnerships team.
* Piyush confirmed that the page had originally been integrated with HubSpot but agreed to verify the current routing and identify exactly where submissions are being recorded.
* Joe clarified that the current routing is incorrect: Blackwell inquiries are being sent into the **provider** workflow when they should be treated as **demand/renter leads**.
* The issue has not prevented leads from being reviewed because the partnerships team checks both categories, but the routing should be corrected.
* Piyush agreed to request HubSpot access and inspect the API configuration responsible for sending lead data.
* Joe offered to help Piyush obtain the required HubSpot access and verify the correct destination.
* Joe also requested that references to **B200** on the page be updated to **B300**, noting stronger current demand for B300 and GB300 resources.
* The supporting copy around the GPU offering will also be reviewed for accuracy.

### Blackwell Page Design Improvements

* Denis recommended simplifying the lower section of the Blackwell lead-generation page.
* He argued that sections such as **Why Choose Akash** and **Ready to Deploy**, along with supporting marketing statistics, are unnecessary once a visitor has already reached the contact form.
* The group agreed that users at this stage have already demonstrated sufficient intent and do not need additional conversion messaging before submitting the form.
* Joe supported removing the unnecessary sections and suggested replacing them with stronger visual content.
* Denis indicated that he had already been considering this design change and will incorporate it into the page improvements.

### GPU & Enterprise Content

* Joe shared that detailed write-ups covering individual GPU models have been completed.
* Sandeep will provide the relevant files/code to Piyush so the content can be integrated into the Akash website.
* The GPU content is intended to become part of the broader enterprise website experience rather than being published as conventional blog posts.
* The material will provide detailed information about individual GPU models while also increasing the amount of authoritative GPU-related information available on the `akash.network` domain.
* A key objective is improving Akash's visibility and usefulness for LLM and AI chat discovery.
* The content does not need prominent homepage placement but should remain accessible and indexable within the website.
* Piyush and Denis will determine the most appropriate placement and presentation for the GPU pages.

### Closing Remarks

* Immediate priorities include verifying Blackwell lead routing, updating provider documentation, correcting outdated Provider Console references, and integrating the completed GPU content.
* Denis will review relevant website pages and calls to action to ensure Home Node and Provider Playbooks are positioned correctly.

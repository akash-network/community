## Meeting Notes

### Opening Remarks

* Tyler Wright welcomed participants and explained that SIG Providers focuses on developments, issues, and feedback related to operating Providers on Akash Network.
* The meeting focused on Provider Console, Home Node, Provider Verification, upcoming releases, and infrastructure improvements.

### Provider Console

* Dval confirmed that Provider Console supported the Provider release issued on July 2 and would continue supporting upcoming Provider releases through its update process.
* Resource Reclamation support is also being explored for Provider Console.
* Future Provider releases are expected to be made easily accessible to operators using Provider Console.

### Akash Home Node

* Significant progress has been made on Home Node, including development of a Windows application that was approaching beta availability.
* Home Node provides an easier way for users with smaller GPU clusters or individual GPUs to contribute resources without operating a full Akash Provider.
* Users with supported GPUs, including RTX 3090, 4090, and 5090 hardware, were encouraged to apply for early beta access.

### Provider Verification

* Phase One of the new Provider Verification process is progressing toward broader testing.
* The team plans to recruit both new and existing Providers to test the verification implementation.
* Additional announcements and testing opportunities were expected over the following weeks.
* Providers were encouraged to maintain the Provider role in Discord to receive announcements and access Provider-specific channels.

### Upcoming Provider Releases

* The Core Team was preparing a substantial Provider release containing approximately fifteen pull requests with multiple features, fixes, and dependency updates.
* Zeke confirmed that several pull requests had already been merged, with final testing planned before release.
* Providers were strongly encouraged to upgrade promptly after release to maintain compatibility with new marketplace functionality and avoid potential bidding issues.
* Another Provider release was expected after an intermediate network upgrade involving additional Provider functionality.

### Provider Infrastructure Improvements

* Development was underway across several infrastructure features, including InfiniBand, ARM Provider support, Resource Reclamation, and Trusted Execution Environment functionality.
* A TEE-enabled Provider had already been operating on Mainnet for approximately one month with generally positive results.
* An issue discovered during testing was being addressed before broader release of the functionality.
* Additional Provider and network releases were expected as these features progressed through testing.

### Provider Audits

* Roger raised questions regarding new Providers waiting for audits and the expected audit timeline.
* Zeke confirmed that he had recently reviewed the outstanding audit requests and completed all except one active audit.
* Community members supporting new Providers were encouraged to communicate updated audit status and continue directing questions through Provider channels.

### Provider Communication & Community Participation

* Providers were reminded to activate the Provider role in Discord to access the Provider uptime channel and receive important release notifications.
* The uptime channel can be used to communicate maintenance and operational updates to the community.
* Tyler encouraged Providers to participate in GitHub discussions and provide feedback on Provider experience, pooling, infrastructure, and desired improvements.
* Community members were also asked to help distribute release announcements across different time zones so Providers can upgrade promptly.

### Closing Remarks

* Tyler reminded participants to monitor Discord for upcoming Provider releases, Home Node beta access, and Provider Verification testing opportunities.
* Providers interested in Phase One verification testing were encouraged to contact Tyler Wright or Joe Deng.
* Community members were encouraged to continue provider-related discussions asynchronously between meetings.

## Action Items
